# M2 手测指引（道路载具互载 / RoRo）

> 目标：验证"卡车在站里等待被运载 → 火车到站把卡车装走 → 火车到另一站把卡车放下 → 卡车继续跑自己排程"这条最小闭环。
> 当前进度：M1（存档骨架，旧档兼容与自读自档已验证）+ M2a（收运/落地事务）+ M2b（订单驱动装卸）+ **M5a（订单窗口 GUI 入口）** 均已完成并编译通过；控制台命令仍保留作备用。

## 0. 用哪个 exe、怎么启动（重要：在 build 目录里启动）

```powershell
cd D:\CNS\ottd\OpenTTD-patches-rvtransport\build
.\openttd.exe -c roro-test.cfg
```

> 说明：`-c roro-test.cfg` 让"个人目录"隔离到 `build\` 下（不会动你 `Documents\OpenTTD` 的配置和存档，也不影响你平时的 JGRPP）。
> 语言包（`build\lang`）与图形基础集（`build\baseset`，含从你个人目录只读复制来的 OpenGFX）都已就位。
> ⚠ 之前给的 `-c testrun\openttd.cfg` 会把工作目录切到 `testrun\`，那里没有 lang/baseset，所以报"无可用语言"——请改用上面这条。

## 0.5 最新修复（请务必用最新 exe 再测）

- **修好了"选择装载/卸载道路载具就提示'不能执行这个命令……'"**：根因是引擎对"订单类型 → 允许修改哪些字段"有白名单，车站订单的白名单里没有这个新字段，命令在参数校验阶段就被拒（不是你操作的问题）。现已加入白名单。
- 非车站订单（车库订单等）不再显示这三项；万一触发会提示"道路载具运输只能设置在车站调度计划上"。
- 新增控制台命令 `rvtransport modify <车辆ID> <订单序号> load|unload|dest`（走与 GUI 完全相同的命令路径，便于排查）。
- 卖出保护：正在被运载的道路载具不能卖；还载着道路载具的载体必须先卸下才能卖。
- 卡车订单里的两项文案改为卡车视角：**等待被运载** / **在此被卸下**（载体上仍是"装载/卸载道路载具"）。
- **已用你保存在 `build\save` 的存档自动验证通过**（三条链路）：
  1. 订单设置：`load` / `unload` / `dest` 三种都返回 OK（火车与卡车都验证过）；
  2. 收运：卡车装上火车后 `flags=2`（被运载）、`hidden=true`，火车 `carrying=1`；
  3. 落地：`detach: ok`，卡车恢复 `flags=0 hidden=false stopped=false` 并出现在新的路站格上。
- ⚠ **请务必重启游戏、用最新编译的 `build\openttd.exe` 再试**：你之前那次"能选但订单没变 / 装不上车"用的是修复前的老 exe（命令被拒 → 订单字段没写进去 → 自然装不上）。

## 1. 搭一个最小场景（GUI 里操作）

1. 新游戏：地图 256×256 即可，**不要加载 NewGRF**（保持干净），资金选"无限制/高"；
2. 建**一个站**，要求它同时具备：
   - **公路停靠站**（卡车停靠站，港湾式或直通式都行，**直通式更推荐**）；
   - **铁路站台**（紧邻建造，会自动并入同一个车站）；
3. 建**公路车库**买 1 辆卡车；建**铁路车库**买 1 台机车（建议再加 1 节车厢）；
4. 在远处再建**第二个站 B**（同样要带公路停靠站；铁路站台可选）；
5. 排程：
   - 卡车订单：`去车站 A`（Go to）；
   - 火车订单：`去车站 A` → `去车站 B`。

## 2. 在订单窗口里设置"装载/卸载道路载具"（M5 已提供 GUI 入口）

1. 打开车辆订单窗口（点车辆 → "Orders"）；
2. 选中要设置的**去车站**订单；
3. 点底部**"装货方式"下拉**（平时显示 No loading / Full load 等的那个），下拉最下面多了两项：
   - **Load road vehicles** — 让这辆车在该站**装载**等待的道路载具（对卡车而言：到站后等待被装走；对火车/船/机而言：到站把等待的卡车装走）；
   - **Unload road vehicles** — 让这辆车在该站**卸下**它载着的道路载具（卡车会被放到该站的公路停靠站格上）。
   再次点同一项可取消（开关式）。
4. 设置好后回到游戏，让车辆按订单跑即可。

**控制台备用方式**（GUI 出问题或想快速验证时）：

```
rvtransport list                          # 看车辆 ID 与状态
rvtransport orderflag <车辆ID> load        # 等价于下拉里的 Load road vehicles
rvtransport orderflag <车辆ID> unload      # 等价于 Unload road vehicles
```

说明：`orderflag` 会同时写"车辆当前订单"和"订单列表中的当前项"；用 GUI 下拉则直接写订单列表项，更稳。

## 3. 期望现象

| 阶段 | 期望 |
|---|---|
| 卡车到达 A 站后 | 卡车**停住不动**（进入"等待被运载"）；`rvtransport state <卡车ID>` 显示 `flags=1`、`stopped=1` |
| 火车到达 A 站后 | 卡车**从路网消失**（画面上看不到它了）；`rvtransport state <卡车ID>` 显示 `flags=2`、`hidden=1`；`rvtransport list` 里火车的 `carrying=1` |
| 给火车打上卸载旗标（`rvtransport orderflag <火车ID> unload`）后火车到达 B 站 | 卡车**出现在 B 站的公路停靠站格**上，随后按自己的订单继续行驶；`rvtransport state <卡车ID>` 显示 `flags=0`、`hidden=0`、`tile` 有效 |
| 全程 | **无崩溃、无断言弹窗**；车辆数量不变（卡车没被销毁/复制） |

## 5. 已知限制（这一阶段属正常现象）

- 尚未做**筛选表达式**（M3）：火车会"见到等待的车就装"，不看目的地是否一致；
- GUI 入口目前只是"装货方式下拉里的两项"（够用；更精致的订单面板要等 M5 其余部分）；筛选表达式（M3）与运载面板尚未做；
- 铰接卡车（多节）暂不支持上下车；
- **不再需要 NewGRF 就能测**（M2d）：新增设置项"装载道路载具需要'超大件'货物类别"，**默认关闭**——任何具备载货容量的车厢/货舱都能装道路载具（原版内容即可测试）。想体验"只有运车专用车才能装"的严格玩法时，可在 设置 → 专家设置（车辆）里打开该开关（此时需要提供 oversized 类货物的 NewGRF，例如运车货列/汽车运输集）。注意 `chinasettrains.grf` 是列车集，不含 oversized 类货物，无法用于严格模式；
- 火车不会为等卡车而延迟发车（"等满载"语义在后续阶段做）；
- 需要绕过一切检查只验证事务时，仍可用 `rvtransport attach <火车ID> <卡车ID> force`。
